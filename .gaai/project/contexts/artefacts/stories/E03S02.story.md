# E03S02 — Upgrade Examples to Current Architecture

## Context

The `/examples` directory and tutorial scripts have fallen behind the recent architectural refactoring (DbC enforcement, shared_python namespace changes, TDD hardening). Examples with broken imports create a poor developer experience and fail in `test_examples.py`.

## Acceptance Criteria

- [ ] All Python scripts in `examples/` execute without raising `ImportError`, `ModuleNotFoundError`, or `AttributeError`
- [ ] All obsolete imports updated to use the current `shared_python` namespace and architecture
- [ ] `test_examples.py` passes (or is created if it doesn't exist) — must exercise at least the top-level import of each example module
- [ ] Any deprecated API calls updated to current equivalents (check CHANGELOG.md for breaking changes)
- [ ] At least one Jupyter notebook (`.ipynb`) in `examples/` validates successfully (runs without kernel errors on the first 5 cells)
- [ ] `ruff check examples/` passes
- [ ] Existing tests unaffected

## Implementation Notes

- Start with: `python -c "import examples.<module>"` for each example to identify broken imports
- Check `src/shared/python/` for correct current module paths
- For Jupyter notebooks: fix cell by cell; do not rewrite notebook from scratch
- If an example references a removed class/function: either update to the new equivalent or add a clear deprecation notice comment
- Focus on fixing, not rewriting — minimal changes to restore functionality

## Scope

`examples/` directory only. No changes to `src/` or `tests/` unless a shared utility is genuinely missing.
