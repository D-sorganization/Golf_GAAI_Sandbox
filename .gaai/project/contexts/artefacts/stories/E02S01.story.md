# E02S01 — live_simulation Pytest Marker

## Context

No tests are marked with `pytest.mark.live_simulation`. Tests requiring a running physics engine, real-time simulation loop, or hardware-in-the-loop must currently either always run (slowing CI) or be unconditionally skipped. A dedicated marker allows selective inclusion/exclusion.

## Acceptance Criteria

- [ ] `live_simulation` marker registered in `pyproject.toml` under `[tool.pytest.ini_options]`:
  ```toml
  markers = [
    "live_simulation: tests that require a running physics simulation engine (MuJoCo, Drake, Pinocchio, etc.)",
  ]
  ```
- [ ] At least 5 existing tests annotated with `@pytest.mark.live_simulation` (select from tests currently guarded by `pytest.skip` for missing engine or conditional imports)
- [ ] `ci-standard.yml` updated to exclude live_simulation tests: `pytest -m "not live_simulation"`
- [ ] `nightly-cross-engine.yml` updated to explicitly include them: `pytest -m live_simulation` (or in addition to normal run)
- [ ] `pytest --co -m live_simulation` returns at least 5 tests
- [ ] `pytest --co -m "not live_simulation"` shows the marked tests excluded
- [ ] Existing tests still pass with the new marker in place
- [ ] `CONTRIBUTING.md` documents the marker and when to use it

## Implementation Notes

- Search for tests currently doing `pytest.skip("requires pinocchio")`, `pytest.skip("requires mujoco")`, etc. — these are candidates
- Also look for `importorskip("pinocchio")`, `importorskip("mujoco")` patterns
- The marker does NOT replace skipif guards for optional packages — it complements them
- Add marker to test function level: `@pytest.mark.live_simulation`
- Check `pyproject.toml` for existing `markers` list before adding (merge, don't replace)
