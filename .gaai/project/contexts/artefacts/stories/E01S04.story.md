# E01S04 — Align GitHub Actions Version References

## Context

CI runs have shown a mismatch: `ci-standard.yml` references `actions/checkout@v4` and `actions/setup-python@v5`, but live runs resolve to `v6`/`v7`. Additionally, `actions/checkout@v6` may not be a published stable release. All workflow files need to be audited and aligned to use consistent, stable, pinned versions.

## Acceptance Criteria

- [ ] All `.github/workflows/*.yml` files audited for action version references
- [ ] `actions/checkout` pinned to the latest stable major version (currently v4; do NOT upgrade to v6 if it's not a published stable release)
- [ ] `actions/setup-python` pinned to the latest stable major version (currently v5)
- [ ] `actions/upload-artifact` and `actions/download-artifact` pinned consistently (v4 family)
- [ ] No workflow references a non-existent action version
- [ ] All version references across workflow files are consistent with each other
- [ ] CI passes after changes

## Implementation Notes

- Verify published releases: `actions/checkout` latest stable is v4 (v4.x.x). v5 does not exist. v6 does not exist.
- Check `gh api repos/actions/checkout/releases/latest` or similar to confirm current stable version
- Focus on: `ci-standard.yml`, `nightly-cross-engine.yml`, and any automation workflows
- Pin to major version tags (e.g., `actions/checkout@v4`) not SHA hashes unless security policy requires it

## Scope

Workflow YAML files only. No Python/Rust code changes.
