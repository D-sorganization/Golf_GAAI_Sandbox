# E01S01 — Fix ruff I001 Import Ordering

## Context

The CI Standard workflow `quality-gate` Lint step fails on branches that include changes to `src/engines/physics_engines/pinocchio/python/dtack/utils/matlab_importer.py`. ruff reports rule **I001** (unsorted import block): the `src.*` first-party import is interleaved with third-party imports without the required isort separator.

## Acceptance Criteria

- [ ] `src/engines/physics_engines/pinocchio/python/dtack/utils/matlab_importer.py` has imports sorted correctly: standard library → third-party → first-party
- [ ] `ruff check src/engines/physics_engines/pinocchio/python/dtack/utils/matlab_importer.py` exits 0 with no I001 errors
- [ ] `ruff format` passes on the file
- [ ] No functional changes to the code — import reordering only
- [ ] All existing tests for this module continue to pass

## Implementation Notes

- Run `ruff check --fix src/engines/physics_engines/pinocchio/python/dtack/utils/matlab_importer.py` to auto-fix, then verify
- The fix is `from __future__ import annotations` first, then stdlib imports (`typing`, `pathlib`), then third-party, then first-party (`src.*`)
- Verify with `ruff check src scripts tests` (the full lint command from CI)

## Scope

Single file fix. No new features, no refactoring beyond import order.
