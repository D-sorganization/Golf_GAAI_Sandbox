# E02S02 — Heavy Integration Tests Workflow

## Context

No `heavy-integration-tests.yml` CI workflow exists. Long-running physics simulation tests are either bundled into ci-standard (slowing feedback) or skipped. This story creates a dedicated workflow that runs on schedule and on-demand.

## Dependencies

- E02S01 must be complete (`live_simulation` marker must exist)

## Acceptance Criteria

- [ ] `.github/workflows/heavy-integration-tests.yml` created
- [ ] Workflow triggers on: `workflow_dispatch`, scheduled weekly (Sunday 2am UTC), and PRs with label `run-heavy-tests`
- [ ] Workflow runs `pytest -m "live_simulation or heavy_integration"` with extended timeout (60 min)
- [ ] `heavy_integration` marker also registered in `pyproject.toml` alongside `live_simulation`
- [ ] Workflow uploads test results as artifact (`pytest-results.xml`)
- [ ] Workflow documented in `CONTRIBUTING.md` (one paragraph on when to trigger it)
- [ ] `ci-standard.yml` explicitly excludes both markers: `pytest -m "not live_simulation and not heavy_integration"`
- [ ] Workflow YAML passes `actionlint` check

## Implementation Notes

- Use `ubuntu-latest` runner; no special GPU runner needed for this story
- Timeout: set `timeout-minutes: 60` at job level
- Results artifact: use `actions/upload-artifact@v4` with `junit-xml` report from pytest (`--junitxml=pytest-results.xml`)
- Pattern the workflow structure after `nightly-cross-engine.yml`
- Use stable action versions consistent with E01S04 findings
