# E04S01 — GUI Launcher Lazy-Loading Enforcement

## Context

The launcher GUI in `src/launchers/` may import heavy physics engine packages (MuJoCo, Drake, Pinocchio) at startup just to render UI tabs, causing slow startup and potential crashes when engines aren't installed. Engine-specific packages must only be imported when the user activates that specific tab/module.

## Acceptance Criteria

- [ ] Audit of all `import` statements in `src/launchers/` completed and documented in a comment block at the top of the primary launcher file
- [ ] No direct top-level `import mujoco`, `import pinocchio`, `import drake` in any launcher file
- [ ] Engine imports moved inside: the function/method that initializes the specific engine tab, or a lazy-loading wrapper using `importlib.import_module()` with `try/except ImportError`
- [ ] Launcher startup time is not degraded (subjective check — it must at least start without a physics engine installed)
- [ ] `src/shared/python/engine_core/engine_availability.py` used for availability checks (do not duplicate logic)
- [ ] At least one test verifying that `import src.launchers.main` (or equivalent entry point) does NOT import `mujoco` or `pinocchio` at module load time — use `sys.modules` inspection
- [ ] All existing launcher tests pass
- [ ] `ruff check src/launchers/` passes

## Implementation Notes

- Lazy pattern:
  ```python
  def _get_mujoco():
      import mujoco  # imported only here, not at module level
      return mujoco
  ```
- Or use `engine_availability.py`'s existing availability check as a guard
- Check `src/launchers/__init__.py` and all files it imports for transitive eager imports
- The test for lazy loading: `import sys; import src.launchers.main; assert "mujoco" not in sys.modules`

## Scope

`src/launchers/` only. No changes to engine implementations.
