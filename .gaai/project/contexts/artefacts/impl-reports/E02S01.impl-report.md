# E02S01 — Implementation Report

## Summary

- Registered `live_simulation` pytest marker in `pyproject.toml` with canonical description matching AC spec
- Updated `ci-standard.yml` to explicitly exclude `live_simulation` tests in the standard CI pytest run
- Added dedicated `Run live_simulation marker tests` step to `nightly-cross-engine.yml`
- Documented the marker in `CONTRIBUTING.md` with usage examples and CI integration notes

## Pre-Implementation State

- `pyproject.toml` already had `live_simulation` in `markers` list but with abbreviated description
- `addopts` in `pyproject.toml` already had `-m "not live_simulation"` globally
- `tests/heavy_integration/test_upstream_contracts.py` already had 6 class-level `@pytest.mark.live_simulation` annotations covering 7 individual tests
- `ci-standard.yml` explicit `-m` flag in workflow DID NOT include `not live_simulation` (overrides addopts)
- `nightly-cross-engine.yml` had no `live_simulation` step
- `CONTRIBUTING.md` had no marker documentation

## Changes Delivered

| File | Change | Purpose |
|------|--------|---------|
| `pyproject.toml` | Updated marker description | AC1: canonical description |
| `.github/workflows/ci-standard.yml` | Added `and not live_simulation` to `-m` flag | AC3: explicit CI exclusion |
| `.github/workflows/nightly-cross-engine.yml` | Added `Run live_simulation marker tests` step | AC4: nightly inclusion |
| `CONTRIBUTING.md` | Added Test Markers section | AC8: documentation |

## No Python Files Modified

All changes were to YAML (workflow), TOML (config), and Markdown (docs). No Python production code was modified.

## Implementation Notes

- The `ci-standard.yml` change is important because explicit `-m` flags in workflow override the `addopts` in `pyproject.toml`. Without the explicit addition, live_simulation tests would have been gated only by `--ignore=tests/heavy_integration` (file-path based), not by marker (semantic intent).
- AC2 (5+ annotated tests) was already satisfied by pre-existing work in `test_upstream_contracts.py` — no new annotations needed.
