# E02S02 — Implementation Report

## Summary

- Created `.github/workflows/heavy-integration-tests.yml` with `workflow_dispatch`, weekly schedule (Sunday 02:00 UTC), and PR label `run-heavy-tests` triggers; runs `pytest -m "live_simulation or heavy_integration"` with 60-minute job timeout and uploads `pytest-results.xml` artifact

## Implementation Notes

- The PR label trigger uses `pull_request: types: [labeled]` at the `on` level, with a job-level `if` expression evaluating `github.event.label.name == 'run-heavy-tests'`. This is the correct GitHub Actions pattern for label-conditional execution.
- Action versions used: `actions/checkout@v4`, `actions/setup-python@v5`, `actions/upload-artifact@v4` — consistent with E01S04 stable version findings.
- The existing `heavy-tests-opt-in.yml` coexists with the new workflow (different filename, different `name:` field, different artifact naming pattern).
- `addopts` in `pyproject.toml` now excludes both markers from default `pytest` invocations, ensuring no accidental slow test runs during local development.
