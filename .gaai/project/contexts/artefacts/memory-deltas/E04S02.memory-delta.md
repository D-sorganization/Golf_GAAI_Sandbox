# E04S02 — Memory Delta

## New Patterns Worth Persisting

### Pattern: Pinocchio Parity Testing Pattern

**Domain:** Engine testing, pinocchio adapter

When writing parity tests for the Pinocchio engine:

1. Always use `pytest.importorskip("pinocchio")` at module top (not per-test)
2. Always annotate with `@pytest.mark.live_simulation` so tests route to heavy-integration workflow
3. Use `FIXTURE_DIR = Path(__file__).resolve().parent.parent.parent / "fixtures" / "models"` to locate URDFs
4. Frame names in `simple_pendulum.urdf`: `world`, `base_link`, `pendulum_link`, `end_effector`; joint names: `world_to_base`, `pendulum_joint`, `pendulum_to_end`

### Pattern: Pinocchio Adapter Protocol Methods

The Pinocchio adapter must expose:
- `get_sensors() -> dict` — returns `{}` (Pinocchio has no native sensor API)
- `compute_affine_drift() -> np.ndarray` — alias to `compute_drift_acceleration()`
- `compute_jacobian()` must call `pin.computeJointJacobians()` internally to guard against stale data

### Pattern: Pre-existing Test Debt

`tests/unit/test_pinocchio_physics_engine.py::test_load_from_path` is a pre-existing test failure — the mock target is `pin` but `BasePhysicsEngine.load_from_path()` validates file existence before delegating to the mockable `_load_from_path_impl()`. This test needs to be redesigned to use `load_from_string()` instead, or mock the `Path.exists()` call. **Not fixed in E04S02 — tracked as separate debt.**

## Decisions

No novel architectural decisions made. All patterns followed existing conventions in `conventions.md`.
