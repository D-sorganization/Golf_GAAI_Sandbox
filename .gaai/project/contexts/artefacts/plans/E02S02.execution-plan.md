# E02S02 — Execution Plan

## Implementation Sequence

### Step 1: Register `heavy_integration` marker in `pyproject.toml`

**File:** `pyproject.toml`
**Change:** Add `"heavy_integration: marks tests as heavy integration tests (long-running, requires full engine stack)"` to the `markers` list under `[tool.pytest.ini_options]`.
**Also:** Update `addopts` to exclude both markers: change `-m "not live_simulation"` to `-m "not live_simulation and not heavy_integration"`.

**Edge case:** The markers list uses a specific format — match existing style exactly. The `addopts` line uses escaped quotes inside a double-quoted string.

**Checkpoint:** `grep "heavy_integration" pyproject.toml` confirms both the marker and the addopts exclusion.

---

### Step 2: Update `ci-standard.yml` to exclude `heavy_integration`

**File:** `.github/workflows/ci-standard.yml`
**Change:** In the `Run Core Test Suite` step, update the `-m` filter from `"not slow and not benchmark and not requires_gl and not requires_network and not requires_gpu"` to also exclude `live_simulation` and `heavy_integration`.

**Current marker filter:** `-m "not slow and not benchmark and not requires_gl and not requires_network and not requires_gpu"`
**Target:** `-m "not slow and not benchmark and not requires_gl and not requires_network and not requires_gpu and not live_simulation and not heavy_integration"`

**Edge case:** The pytest run uses `xvfb-run` with other flags — only change the `-m` argument value.

**Checkpoint:** Verify the updated line contains both `not live_simulation` and `not heavy_integration`.

---

### Step 3: Create `.github/workflows/heavy-integration-tests.yml`

**File:** `.github/workflows/heavy-integration-tests.yml` (new file)

**Triggers:**
- `workflow_dispatch` (manual)
- `schedule: cron: "0 2 * * 0"` (weekly Sunday 2am UTC)
- `pull_request` with `types: [labeled]` and label condition: `github.event.label.name == 'run-heavy-tests'`

**Job structure (pattern from `nightly-cross-engine.yml`):**
- `runs-on: ubuntu-latest`
- `timeout-minutes: 60`
- Python 3.11
- Install `.[dev]` plus heavy extras (pinocchio, mujoco)
- Run `pytest -m "live_simulation or heavy_integration"` with `--junitxml=pytest-results.xml`
- Upload `pytest-results.xml` via `actions/upload-artifact@v4`

**Action versions (consistent with E01S04 stable versions):**
- `actions/checkout@v4`
- `actions/setup-python@v5`
- `actions/upload-artifact@v4`

**Edge cases:**
- PR label trigger: must use `if: github.event.label.name == 'run-heavy-tests'` at job level or use conditional step, so the job only runs on the right label event
- Workflow name must not collide with `heavy-tests-opt-in.yml` (different filename, different `name:` field)
- `actionlint` requires `workflow_dispatch` inputs block to be valid YAML; keep inputs optional

---

### Step 4: Add documentation paragraph to `CONTRIBUTING.md`

**File:** `CONTRIBUTING.md`
**Location:** Add a new section after the existing Testing section
**Content:** One paragraph explaining: what `heavy-integration-tests.yml` does, when to trigger it (PRs with `run-heavy-tests` label, or manually from Actions tab), and that it runs weekly on Sundays automatically.
