# E02S01 — Execution Plan: Register live_simulation pytest marker and annotate candidate tests

## Pre-Analysis Summary

After codebase reconnaissance, the following was found:

- `pyproject.toml` already has `live_simulation` marker registered (line 279) but with description `"tests requiring live physics/math engines"` — AC1 requires the canonical description.
- `addopts` in `pyproject.toml` already includes `-m "not live_simulation"` globally.
- `tests/heavy_integration/test_upstream_contracts.py` already has 5 classes annotated with `@pytest.mark.live_simulation` (AC2 satisfied).
- `ci-standard.yml` pytest run uses explicit `-m "not slow and not benchmark and not requires_gl..."` that does NOT include `not live_simulation` — needs updating (AC3).
- `nightly-cross-engine.yml` does NOT include `-m live_simulation` on the heavy integration test run — needs updating (AC4).
- `CONTRIBUTING.md` does not document the marker — needs updating (AC8).

## Implementation Sequence

### Step 1 — Update pyproject.toml marker description (AC1)

**File:** `pyproject.toml`

Change line 279 from:
```
"live_simulation: tests requiring live physics/math engines",
```
To:
```
"live_simulation: tests that require a running physics simulation engine (MuJoCo, Drake, Pinocchio, etc.)",
```

Edge case: The `addopts` already has `-m "not live_simulation"` — do not duplicate it.

### Step 2 — Update ci-standard.yml (AC3)

**File:** `.github/workflows/ci-standard.yml`

The "Run Core Test Suite" step uses `-m "not slow and not benchmark and not requires_gl and not requires_network and not requires_gpu"`.

Add `and not live_simulation` to this filter to make the exclusion explicit in the workflow (even though `addopts` already handles it globally, the explicit workflow `-m` flag overrides `addopts`).

Edge case: The `--ignore=tests/heavy_integration` already prevents `test_upstream_contracts.py` from running, but adding `not live_simulation` to the explicit `-m` filter makes the intent crystal-clear and handles any future live_simulation tests outside heavy_integration.

### Step 3 — Update nightly-cross-engine.yml (AC4)

**File:** `.github/workflows/nightly-cross-engine.yml`

The "Run cross-engine validation tests" step runs `pytest tests/heavy_integration/test_cross_engine_integration.py`. The AC requires adding `pytest -m live_simulation` (or in addition to normal run).

Add a new step or add `-m live_simulation` to run `tests/heavy_integration/` specifically with the marker filter.

### Step 4 — Update CONTRIBUTING.md (AC8)

**File:** `CONTRIBUTING.md`

Add a "Test Markers" section documenting:
- `live_simulation` marker
- When to use it
- How to run/exclude

## Test Checkpoints
